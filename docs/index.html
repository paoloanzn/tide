Your Solana network.
Written as code.

Tide is a programming language for describing local Solana environments: accounts, programs, tokens, initial state, bootstrap transactions and executable scenarios in one source file.

Explore the language → Real-protocol gallery

Designed for humans to review and AI agents to generate. Uses Agave solana-test-validator today.

The mental model

One language for the whole setup.

Declare the state you need, run the initialization that requires real transactions, then verify the environment. No separate configuration language is required for these phases.

hello.tid
keypair alice = seed("alice");
keypair bob = seed("bob");

network hello {
  genesis {
    account alice.pubkey { lamports = 10 SOL; }
    account bob.pubkey { lamports = 1 SOL; }
  }

  scenario funded {
    assert balance(alice.pubkey) == 10 SOL;
  }
}
// Excerpt of examples/01-simple-pda/network.tid
bootstrap {
  invoke PROGRAM with {
    method = "run";
    accounts = {
      sender: caller.pubkey,
      custom: custom,
      system_program: system_program()
    };
    signers = [caller];
  };
  assert exists(custom);
}

scenario initialized {
  let state = decode(CustomAccount, account_info(custom).data);
  assert state.counter == 1;
}
// Excerpt of examples/02-subscriptions/network.tid
genesis {
  program subscriptions {
    id = SUBSCRIPTIONS;
    binary = "upstream/target/deploy/subscriptions_program.so";
  }
  mint usd.pubkey {
    decimals = 6;
    mint_authority = merchant.pubkey;
    supply = 3000 * UNIT;
  }
  for user in wallets {
    account user { lamports = 10 SOL; }
    associated_token_account ata(user, usd.pubkey) {
      mint = usd.pubkey;
      owner = user;
      amount = 1000 * UNIT;
    }
  }
}

Built for an agent-assisted workflow

Give your agent a protocol. Keep the environment readable.

Ask an agent to inspect the program, create a Tide network and iterate on compile or runtime errors. The outcome is an explicit, versioned environment that can be reviewed without opening a chain of unrelated setup tools.

01

Specify

Define which accounts and programs should exist at genesis, with deterministic local keys and typed fields.

02

Bootstrap

Initialize application state with real transactions, pre-load binaries or clone selected remote accounts.

03

Verify

Run named scenarios and inspect errors with source locations. Then connect your backend or frontend to the RPC.

Get started

Install Tide. Describe your network.

Install the experimental CLI, then run tide check, tide up and tide down. The local validator requires the Solana/Agave CLI.

curl -fsSL https://raw.githubusercontent.com/paoloanzn/tide/main/install.sh | sh

Review third-party shell scripts before executing them. Installer checks release SHA-256 checksums. Linux and Apple silicon macOS binaries are available.

Current limitations. Tide v0.1.0 has one test-validator backend; fork copies the feature set, not the entire remote state. Remote account clones reflect current upstream data. Snapshot, restore, time travel, multi-validator execution and package distribution are not yet implemented. Avoid publicly derived seed keys on real networks.
